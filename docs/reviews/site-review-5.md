# Site review 5 — earn every screen

Reviewed 2026-10-25 against Concept A and a Vercel/Stripe-level quality bar.
This is an independent assessment within this review, not an external reviewer
or an inherited score. Target: at least 9/10 on desktop and mobile.

## Baseline and method

Baseline commit: `6695364`. Visually inspected all 16 images in
`screenshots/site/final/`: both full homepages, first viewports, Getting started
viewports and the two mobile comparison states, in dark and light. Read round 4,
the product plan's positioning/design/site/docs requirements, and the art
checklist. The existing images are recoverable from that commit. `design/`
remains read-only.

## Pre-fix verdict

**Desktop 8.3/10. Mobile 7.8/10.** A competent, credible development site. It does
not yet have the ruthless editing or navigational fluency of the references.
The actual artwork and honest provenance carry more of the quality than the
page composition does. These scores intentionally differ from round 4.

Ranked issues:

1. **Mobile spends too many screens saying the same thing.** The toolkit outline
   restates the three steps immediately underneath; file-format boxes restate
   adjacent prose; two closing invitations compete. After the artwork, almost
   everything has the same visual weight. Removing repetition matters more
   than decorating another card.
2. **Mobile docs make the reader wait.** Global links, build metadata, title,
   three tall task shortcuts and exploratory copy push the first instruction
   to the bottom of a 900px screen. The page also lacks a complete section index.
   A phone should offer navigation on demand and put the task in view.
3. **The mobile hero still delays its strongest evidence.** The artwork starts
   below a redundant window label, and the actual session excerpt is below the
   first viewport. “Desktop” appears twice around the secondary action. Keep
   the platform disclosure, but spend less height on its presentation.
4. **The proof is accurate but asks the reader to find a tiny change.** The
   three-cell edit cannot substantiate a broad autonomous-building claim.
   Explain where to look, keep the identical-camera comparison, and retain the
   modest claim. A larger recorded build remains separate production work.
5. **Desktop docs have unused room and weak orientation.** The broad reading
   column and empty right edge lack the section navigation expected of a
   professional reference. Add a real generated index, including without JS.
6. **The lower page has no decisive ending.** A browser invitation followed by
   another source invitation dilutes both. Give the page one conclusion and put
   source/license actions alongside it.

## Changes made

- Removed the illustrative toolkit block that repeated the three workflow steps;
  kept a direct link to the executable MCP tutorial. Reworked those steps into
  three columns on desktop and a concise sequence on phones.
- Removed the redundant format boxes and combined the two closing invitations.
  Source and MIT information now support one clear closing action. Tightened
  editor copy and aligned mobile feature text beside the small symbols.
- Removed the mobile window-label bar, reduced caption overhead, and moved the
  native-only session disclosure into the existing recorded-session caption.
  The full artwork and entire session excerpt now fit in the 390×900 viewport.
  Desktop-only browser labeling remains next to its action; native session
  limitations remain explicit in the closing section and setup guide.
- Added a static section index generated by Rust from actual article headings.
  Wide screens have a separate right-hand index and a 720px reading column.
  Phones and tablets have native Browse docs / On this page disclosures.
  They work without JavaScript. Optional dismissal handles Escape with focus
  restoration, outside clicks, and same-page navigation with heading focus.
- Replaced the tall setup shortcut stack with two direct task links, shortened
  the exploratory note, and wrapped the actual build command across shell lines.
  The first complete command now fits the phone viewport, without horizontal
  scrolling at 390px. Larger examples retain their normal code scrolling.
- Added a specific visual cue for the comparison: watch the lower-left edge of
  the amber cluster. Original PNGs and provenance remain intact. No larger
  agent-building claim is made from this three-cell demonstration.
- Removed a duplicate mobile divider found during recapture and expanded the
  header navigation and mobile browser action to 44px touch targets.

## Post-fix verdict

**Desktop homepage 8.8/10. Mobile homepage 8.7/10.** Better edited, substantially
more useful on a phone, and still below the requested 9+ reference standard.
These are judgments of the final images, not rewards for completing tasks.

| Surface (both themes) | Before /10 | After /10 | What the final captures show |
| --- | --- | --- | --- |
| Desktop homepage | 8.3 | 8.8 | Strong product-led opening, cleaner proof-to-workflow transition, and one decisive conclusion. The native chrome is still tiny inside the marketing image. |
| Mobile homepage | 7.8 | 8.7 | The artwork and entire recorded session fit the opening screen. Fewer repeated explanations and a clearer route to setup. The middle still relies on a familiar sequence of text rows. |
| Desktop Getting started | 7.8 | 8.6 | A controlled reading width, a useful section index, and clear task links. Long technical reference navigation still needs search. |
| Mobile Getting started | 7.2 | 8.5 | Navigation takes one compact row; menus have readable 44px links. The complete build command is visible in the first screen. Setup is still a long, mixed-task document. |

Dark and light receive equal scores. Both keep the restrained neutral system,
legible metadata, real artwork and clear controls. The light disclosures have a
soft floating shadow; the dark disclosures use their border against pure black.

At the captured sizes, the mobile homepage falls from **5,155px to 4,109px**
(about 20% shorter). Desktop falls from **4,167px to 3,586px** (about 14%). This is
content editing and composition, not smaller body type. The separate viewport
images demonstrate the first-screen claim; full-page thumbnails alone cannot.

Remaining issues, ranked:

1. **The evidence ceiling is still low.** Three voxels show that a tool call
   reached a model; they do not show an agent composing, inspecting and correcting
   a meaningful object. A reproducible multi-step build with readable decisions
   would add more credibility than another layout adjustment.
2. **One workshop cannot carry a full creative-tool launch.** The site needs the
   planned curated showcase with varied silhouettes and genuine process evidence.
   Repeating this fixture or inventing an agent-made gallery would not close it.
3. **Docs still lack search and task separation.** The generated section index
   fixes orientation, not cross-page discovery. Build/install, host connection,
   human editing and the MCP tutorial should eventually have focused guides.
4. **The lower mobile narrative remains conventional.** It is shorter and more
   deliberate, but a distinctive process example should eventually replace more
   feature prose. The desktop screenshot's small chrome remains a secondary
   weakness; its full-resolution source is still linked.

## Evidence and verification

Ran `node scripts/capture-site.mjs screenshots/site/final` after the fixes and
visually inspected all **20 captures**: desktop/mobile full pages and first
viewports, desktop/mobile Getting started, both mobile comparison states, and
both mobile documentation menus, each in dark and light. Chromium version,
page heights and individual captures are in `verification.json`.

- `scripts/build-site.sh --skip-web`: Rust docs regenerated; existing verified
  editor bundle copied unchanged. No app code or wasm build input changed.
- `python3 scripts/check-site.py`: 7 pages, 295 local links/assets, all 38 tool
  schemas, downloadable skills and bundled editor parity pass.
- Browser suite: homepage and all five docs routes fit 320, 390, 768, 1024 and
  1440px in both themes. Section indexes exactly match article headings.
- Browser interactions: theme persistence, decoded assets, clipboard contents,
  keyboard skip link, reduced motion, comparison controls, disclosure exclusion,
  Escape/focus restoration, outside dismissal and anchor focus pass. Navigation,
  comparison and the new docs menus also work with JavaScript disabled.
- The complete native-session excerpt fits the 390×900 hero. The first docs build
  example fits that viewport and needs no horizontal scrolling. These are checked
  geometrically as well as visually. No homepage third-party requests or
  homepage/docs runtime errors were observed.
- `cargo build --locked --workspace`: passes, including native GPUI on Linux.
- `cargo test --locked --workspace`: **112 passed**, including the published
  create → batch → render → save → GLB tutorial. The site tests passed again after
  the final documentation edits.
- `cargo clippy --locked --workspace --all-targets -- -D warnings` and
  `cargo fmt --all -- --check`: pass. Site-specific Clippy also passed after the
  last generator changes.
- Bundled `/app/?backend=webgl` opened Autumn Workshop under headless Chromium
  with SwiftShader, produced a 339,615-byte screenshot and no page errors. The
  resulting editor image was visually inspected.

This is not a screen-reader audit or a claim that the full product/release plan
is complete. No files under `design/` changed. No push, deployment or remote
creation occurred.
