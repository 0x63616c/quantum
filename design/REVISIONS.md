## Plan — round 2 critique

Reviewed 2026-10-25 as principal engineering/product review against [ART-CHECKLIST.md](ART-CHECKLIST.md). Baseline is [PLAN-v2.md](plan-history/PLAN-v2.md), byte-identical to PLAN.md at review start. **Verdict: strong coverage, insufficiently closed contracts.** Round 1 correctly leads with the optimal editor for agents and includes the human editor, documentation, integrations, showcase and release surfaces. Repeating those requirements would not improve this revision. The remaining problem is that plausible individual paragraphs contradict one another at boundaries. Implementing them literally would produce lost geometry, changing file identities, ambiguous retries, an unusable ninth document, and a release/update pipeline with unproven recovery. “Spec-first” must resolve these decisions before handlers exist.

The dated 2026-07-28 spec is available and changes lifecycle, state and cancellation. SDK support alone proves neither profile. | Explicit 2025-11-25 and 2026-07-28 transport profiles; object-shaped schemas compatible with both; Voxelite authority/client identity independent of MCP connection state; real tests for each transport/profile and disconnect-before-commit. |
| R2-02 — Major | Eight open models and sixteen artifacts have no close/release tools. Agents cannot rename/resize a model or inspect changes since a revision. | R2-03 — Blocker | `.voxl` promises byte-identical round trips but MCP import normally returns new IDs. | R2-04 — Major | Transform move clears source before `collision=skip`, which can erase cells whose destination was skipped. Reflection/rotation/translation order is unspecified. Primitive “generated/visited” budgets count vaguely; batch allows palette import despite forbidding I/O. | Reject skip for moves; fix transformation order and integer tie rules; count inspected/generated work and reserve history before commit. | R2-05 — Blocker | Epoch changes invalidate operation IDs while recovery claims persisted deduplication; no precise crash acknowledgement or operation query rule spans restarts. Concurrent identical IDs can both be preparing. | Epoch on every mutation; reserve in-flight IDs; persist result plus patch atomically before MCP success; query previous epochs explicitly; never replay an unknown old-epoch mutation. Distinguish native durable success from volatile UI/web commits. |
| R2-06 — Major | Export/save is described as an agent success without explaining how host users obtain artifacts. A large artifact cannot reasonably be piped through hundreds of model-visible base64 calls. Image duplication also lacks a token/result-size policy. | Direct app download/Save As and CLI session export through authenticated IPC; compact contact-sheet default plus four image handles; encoded response budget; all four hosts complete artifact retrieval, including Desktop without shell access. |

| R2-09 — Major | Cursor's required full plugin path is correct but path-variable handling is left to packaging. | R2-10 — Blocker | The updater promises a sequence of renames survives every power loss, without specifying what starts recovery when the app path is absent or broken. Open-in-web gallery assets live on another deployment despite a same-origin-only rule. | Separate validated product commit, content commit and release manifest; promote tested binaries without rebuild, immutable docs/assets before mutable pointers, N/N−1 checks and rollback. Copy hash-listed gallery models to the app deployment's own asset root. |
| R2-13 — Major | Performance numbers lack sample counts/cold-warm definitions; 1.5M quads is not an allocation layout. Maximum-size input and staged parser/Blob memory may exceed browser budgets. | R2-15 — Major | M0 is effectively a miniature product, owners are sometimes joint, and 33 reviews are counted without capacity or a concrete deliverable list.
