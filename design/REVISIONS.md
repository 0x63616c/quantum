# Plan revision record

## Plan — round 1 critique

Reviewed 2026-10-24 against the requested product contract and [ART-CHECKLIST.md](ART-CHECKLIST.md). Baseline: [PLAN-v1.md](plan-history/PLAN-v1.md), copied byte-for-byte before edits. This is a planning review; no application implementation or runtime validation is implied.

**Verdict: not ready to implement as the agreed product.** The document has useful engineering detail, but optimizes a conventional human editor with MCP added late. Several explicit launch requirements have no deliverable, and the release definition permits incomplete distribution. Correct low-level details do not compensate for missing product contracts.

| Severity | Finding in the baseline | Required correction and acceptance evidence |
| --- | --- | --- |
| Blocker | Opening positioning and goals lead with “Aseprite-style”; MCP integrates after the artist workflow in M4. The marketing section leads with generic editing. | Lead with the optimal voxel editor for AI agents, fully excellent for humans. Build spec → headless agent loop → live human view early. Marketing, README, onboarding, skills, and benchmarks must prove that promise. |
| Blocker | §5 ZIP plus binary chunks is inspectable after decoding, but ordinary Git diffs and text-editing agents cannot use it directly. Deterministic compression is also asserted without a tested cross-target implementation. | Make canonical, bounded, versioned text `.voxl` the default; define coordinate ordering, stable IDs, canonicalization, validation, migration, and one-voxel diff acceptance. Runtime chunk storage need not dictate the portable format. |
| Major | A voxel array and box tool do not constitute a rich composition API. No mixed atomic batch, sphere/cylinder/line primitives, region transform/copy, dry-run validation, or compact semantic inspection. | Specify shapes mathematically, bounded composition, preflight, explicit coordinates/palette names, and one atomic history item per batch. Execute example fixtures through the same command engine as the UI. |
| Major | “Schemas” is not a versioned API design process. Tool names mix verbs and nouns; no example per tool, compatibility/deprecation rule, or generated-reference coverage gate. | Freeze a versioned specification before handlers, consistent names, structured inputs/outputs/errors, examples for every tool, and CI preventing undocumented tools or schema drift. Distinguish Voxelite API, file format, session wire, MCP protocol, and app versions. |
| Major | Agent undo is blind shared-stack undo. No history listing, expected entry ID, checkpoints, or operation-result query after a timeout. Single-view camera construction imposes avoidable agent work. | Expose discoverable labeled history, safe top-entry checks and checkpoint restore semantics, retry lookup, and named multi-angle renders captured at one revision. Test intervening human edits and failed/retried operations. |
| Major | Headless is only a server flag. CLI loading, saving, batch application, format validation, rendering, errors, GPU availability, and unattended execution are unspecified. | Add an actual CLI contract with commands, exit codes, JSON output, no GUI dependency, atomic saves, and a reproducible no-window build/render/export workflow. |
| Major | Live sync has sound transport detail but no required agent activity panel or usable control of a running session. | Make activity, origin, changed bounds, revision, progress, cancel-before-commit, pause, disconnect, and safe undo visible; prove a human can watch and intervene without losing edits. |
| Blocker | §8 gray backgrounds and Inter conflict with the checklist's updated pure-black Vercel/Stripe direction. Tokens are not governed across app/site/docs. | Define #000 dark / #fff light surfaces, Geist/Geist Mono, restrained accent, hairlines, shared source/generation, state specimens, and cross-surface visual checks. Decorative hairlines must not be confused with accessible control boundaries. |
| Major | Shortcuts exist, but command palette, first-run paths, empty/loading/error states, and onboarding success criteria are absent. Accessibility is deferred despite uncertain GPUI support. | Specify first agent/human journeys, searchable actions, keyboard model editing, screen-reader semantics, and first-run usability trials. Prove essential native and wasm accessibility in M0. |
| Blocker | A `docs/` directory is not a professional documentation site. There is no IA, search, reference renderer, host install page, version policy, editorial standard, or deployment gate. | Deliver a separate Vercel docs site with the complete requested guides, generated tool reference, examples, search/version switcher, tested snippets, responsive accessibility, and release-linked content. |
| Blocker | Ready-made agent skills and first-class Cursor/Codex/Claude integrations are entirely absent. | Ship `skills/` source, host prompts/rules/configs, Cursor plugin with one-click marketplace installation, Codex MCP + skills/AGENTS.md, Claude Code and Desktop packages, per-host install pages, clean-profile tests, upgrade/uninstall paths. Do not call an MCP-only deeplink a complete plugin install. |
| Major | Marketing has one sample/screenshot but no showcase gallery, interactive previews, content pipeline, or separate post-v1 art-production milestone. | Define a substantial original gallery with exported GLBs, accessible rotating previews, `.voxl` downloads, provenance and reproducible MCP recipes. Schedule production after v1 works; make gallery launch an explicit later gate. |
| Major | No benchmark methodology or demo recording deliverable substantiates the agent positioning. | Define tasks, pinned host/model/tool/skill versions, repeated runs, success criteria, call/token/time accounting, failure reporting, and sanitized recordings published with downloadable artifacts. Avoid fabricated universal superiority claims. |
| Blocker | M7 says signed/notarized builds “if credentials exist.” Auto-update and Homebrew cask are missing; changelog is only a bullet. | Signing and notarization are mandatory public-v1 gates. Add tested authenticated updates/rollback, protected release pipeline, cask install/upgrade/uninstall, changelog/versioned-docs synchronization, and a credential-readiness gate early. Unsigned development artifacts cannot close public release. |
| Major | Performance has a useful 250k-voxel fixture but no complete large-model load/save/shape/render targets. Mesh, model, snapshots, history, and wasm budgets are not reconciled. OOM recovery is too casually promised. | Add reproducible 1M-voxel and pathological fixtures, bounded aggregate memory/geometry budgets, interactive/CLI timings, explicit backend limits, and preflight admission. | Major | At least 24 reviews is process, not a capacity plan. Ownership, critical path, exit evidence, host marketplace lead time, release rehearsals, and post-v1 showcase sequencing are missing. | Give every milestone an accountable role, dependencies, concrete gates, scope boundaries, staffing assumptions, and a re-estimation point after spikes. Retain three substantive critique/fix rounds per milestone without pretending they establish schedule feasibility. |

### Technical fact check

| Claim checked | Result and planning consequence | Primary evidence |
| --- | --- | --- |
| GPUI web support exists upstream. | Confirmed: PR #50228 merged on 2026-02-26. It describes a basic web platform; it does not prove Voxelite's 3D composition, accessibility, browser parity, or performance. | [Upstream PR](https://github.com/zed-industries/zed/pull/50228) |
| The unofficial GPUI family can be treated as a safe production pin. | Partly established: `gpui-unofficial` documents 1.25.3 and Apache-2.0, but also says the distribution needs a maintainer. Web/platform registry endpoints could not be fetched in this review. Do not describe the whole family as freshly verified; inspect exact manifests and compile all targets in M0. | [Publisher documentation](https://docs.rs/gpui-unofficial/latest/gpui/) |
| GPUI web threading and WebGL2 are straightforward. | Manifests confirm default multithreading, a nightly `parking_lot` feature, and wasm `wgpu/webgl`. Feature presence does not prove the full GPUI shader stack or browser runtime works. Retain a hard executable feasibility gate. | [gpui_web manifest](https://raw.githubusercontent.com/zed-industries/zed/main/crates/gpui_web/Cargo.toml), [gpui_wgpu manifest](https://raw.githubusercontent.com/zed-industries/zed/main/crates/gpui_wgpu/Cargo.toml) |
| `wgpu` and `rmcp` capabilities are real. | Confirmed: wgpu documents Metal/WebGPU/WebGL2; rmcp docs show 3.7.0, official Rust SDK status, stdio and Streamable HTTP features. This does not establish a compatible project lockfile or GPU-free rendering. | [wgpu](https://docs.rs/wgpu/latest/wgpu/), [rmcp](https://docs.rs/rmcp/latest/rmcp/) |
| Vercel requires a local companion because Functions cannot use WebSockets. | That would be false; the baseline correctly notes documented public-beta WebSockets and duration constraints. Keep the local authority because of the product's offline/local architecture, not an obsolete vendor limitation. Static prebuilt hosting is supported. | [Vercel WebSockets](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections), [Build Output API](https://vercel.com/docs/build-output-api) |
| Agent installation can be a generic MCP snippet. | Insufficient: Cursor supports plugins containing rules/skills/MCP and separately MCP deeplinks; Codex has its own MCP configuration, skills discovery, and AGENTS.md behavior; Claude Code/Desktop require distinct instructions. | [Cursor plugins](https://cursor.com/docs/plugins), [Cursor manifest reference](https://cursor.com/docs/reference/plugins), [Codex MCP](https://developers.openai.com/codex/mcp), [Codex skills](https://developers.openai.com/codex/skills), [Codex AGENTS.md](https://developers.openai.com/codex/guides/agents-md), [Claude Code MCP](https://code.claude.com/docs/en/mcp), [Claude Code skills](https://code.claude.com/docs/en/skills), [Claude Desktop local MCP](https://support.anthropic.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop) |
| Signed releases and a Homebrew cask are interchangeable with a ZIP download. | False as a release contract: notarization needs a specific submission/stapling workflow; casks declare version, checksums and app/binary artifacts. Neither supplies Voxelite's updater automatically. | [Apple notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow), [Homebrew cask specification](https://docs.brew.sh/Cask-Cookbook) |

Research establishes vendor capabilities, not implementation readiness. The replacement plan must label all future builds, tests, benchmarks, artwork, deployments, marketplace approvals, and signing as pending work.
